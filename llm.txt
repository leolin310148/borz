# borz

> A single-binary Go CLI that drives any Chromium browser via the Chrome DevTools Protocol. It ships a daemon, a stdio MCP server, and a remote-accessible HTTP/REST server, so humans, shell scripts, workflow tools, and AI agents can all share the same live browser session (cookies, logins, extensions, JS state).

## Why use it

- Real Chrome, real session: operates on the user's logged-in browser. Built-in `fetch`-style tools can't log in, run JS, or see the rendered DOM.
- Three front-ends over one daemon: CLI, MCP (stdio), HTTP/REST (`/v1/*`). Pick the integration that fits.
- Zero runtime deps. Single static binary.

## Install

```bash
# macOS (Apple Silicon)
curl -LO https://github.com/leolin310148/borz/releases/latest/download/borz-darwin-arm64
chmod +x borz-darwin-arm64 && sudo mv borz-darwin-arm64 /usr/local/bin/borz
# Or: go install github.com/leolin310148/borz@latest
```

## Core model

Everything is a request → dispatched over CDP → JSON response `{id, success, data?, error?}`.

Interactive elements are identified by numeric refs returned from `snapshot`. The workflow is always: **snapshot → act on refs → snapshot again**.

Every response carries a short `tab` id (e.g. `ab1c`); pass it as `--tab <id>` (CLI), `tab` (MCP), or `tab`/`tabId` (REST) to target a specific tab.

## CLI cheat sheet

```bash
borz open <url>                              # reuses tab with same URL; --new forces fresh
borz open <url> --wait-for '<selector>' [--timeout <ms>]  # block until selector found (10s default)
borz <any-cmd> --pre-delay <ms>              # sleep N ms before the action (replaces 'sleep N && borz ...')
borz <any-cmd> --post-delay <ms>             # sleep N ms after a successful action (use --wait-for when a selector exists)
borz snapshot [-i] [-c] [-d N] [--role role] # accessibility tree with refs
borz snapshot --text-only                    # reader-mode plain text (no refs)
borz snapshot --diff                         # only +/-/~ changes since last snapshot of this tab
borz viewport [mobile|tablet|desktop|WxH|reset]  # responsive viewport emulation
borz click <ref>                             # refs come from snapshot
borz fill <ref> <text>                       # clear + fill
borz type <ref> <text>                       # append
borz upload <ref> <file...>                  # attach files to <input type=file> (paths on daemon host)
borz filechooser accept <file...>            # arm the next native file-picker dialog (no <input> needed)
borz webauthn enable|add|credentials|remove [--tab id]  # typed Passkey virtual-authenticator lifecycle
borz webauthn set-user-verified <id> <bool>   # control UV result; set-automatic-presence controls presence
borz press <key> [--modifiers <csv>] [--commands <csv>]  # Enter, Tab; modifiers: alt,ctrl,meta,shift
                                             # meta combos (a/c/x/v/z) auto-map to CDP editing commands
borz clipboard-write <text> [--paste]        # set clipboard; --paste fires Ctrl+Shift+V (atomic terminal paste)
borz term-text                               # xterm.js buffer text incl. scrollback (replaces screenshot OCR)
borz eval <script>                           # JS in page context, returns JSON
borz eval --unwrap <script>                  # print result raw (strings unquoted)
borz eval --file <path>                      # read script from disk
borz eval --file ./x.js --json-arg user='{"id":7}' --json-arg n=3   # inject JSON args as top-level consts
borz eval "await fetch('/x').then(...)"      # top-level await auto-wraps in async IIFE
borz screenshot                              # base64 PNG in JSON; snapshot ref highlights excluded
borz get <url|title|text|href|value|class> [ref]
borz network [requests|clear] [--filter] [--method] [--status code|class] [--with-body] [--limit n]
borz network requests --tail [--interval duration|ms]   # live stream of new requests (Ctrl+C to stop)
borz console [--clear] [--filter] [--tail]  # --tail streams new messages
borz errors [--clear] [--filter] [--tail]   # --tail streams new JS errors
borz fetch <url> [--method POST] [--header 'Name: value'] [--body data]  # authenticated HTTP via page
borz tab                                     # list; "tab new", "tab 2", "tab close 1"
borz tab front                               # bring the tab to the real OS foreground (unminimize + focus)
borz page visibility visible|hidden|reset    # override document.visibilityState without moving a window
borz frame <selector> | main                 # iframe switching
borz dialog accept|dismiss [text]
borz trace start|stop|status
borz extension status                      # optional Chrome extension capabilities
borz cookies all [domain]                  # all-domain cookie store (extension)
borz bookmarks tree|search|create|update|remove
borz browser-history search [query] [--limit N]
borz downloads list|search|start|erase|cancel|pause|resume
borz window list|new|focus|close           # browser windows (extension)
borz site list|search|info|run [--scope client|server]  # client catalog by default; server = selected daemon
borz site update|new|lint|trust             # manage client-side adapters
borz <platform>/<adapter> [args]            # shorthand for "site run"
borz status | daemon [status|restart|shutdown] # restart replaces only daemon and preserves Chrome; status is read-only
borz doctor [--json]                         # diagnose CLI/daemon/CDP/tabs end-to-end
borz browser status|adopt [--port N]         # which Chrome borz owns; adopt fixes an identity mismatch
borz logs path|tail|stats [--since 7d]       # inspect privacy-safe local operational logs
borz feedback <msg> [--category c] [--command cmd]  # record borz-improvement feedback to ~/.borz/feedback.jsonl (list|path to review)
borz server --host 0.0.0.0 --token ... [shutdown]
borz profile list|show|add|set|rm            # named browser targets (profiles.json)
borz help [command [sub]]                    # per-command help
borz <command> --help                        # same, inline form
```

Use `borz daemon restart [--json]` for a version refresh or stale default-profile daemon: it verifies the exact local PID through loopback `/healthz`, forcibly replaces only the daemon, and preserves the managed Chrome process, tab IDs, and session. A named profile with missing daemon state is refused because its dynamic port cannot be safely guessed. The command also refuses remote/non-loopback/unverified targets and interrupts in-flight daemon work. Shutting down an auto-started daemon is different: `borz daemon shutdown` performs graceful cleanup and also closes its borz-owned managed Chrome instance. Browsers attached through a `cdp` profile remain externally owned and are never closed by daemon shutdown. `server --ensure-browser` closes Chrome only when its ensure hook actually launched that instance.

`borz doctor --json` includes a `Binary PATH` check before browser diagnostics. It safely inspects (never executes) every distinct `borz` on PATH and returns canonical path, embedded version, SHA-256, `current`, and `matchesCurrent`. Treat multiple separate copies as drift risk even if their hashes currently match; keep one canonical install and symlink compatibility paths to it.

Global flags: `--profile <name>`, `--tab <id>`, `--json`, `--jq <expr>`, `--unwrap` (eval/site only), `--since <seq|last_action>`.

## Profiles (one handle per browser target)

`~/.borz/profiles.json` (0600) declares what each profile name means; select one
with `--profile <name>` or `BORZ_PROFILE`. Undeclared names (including
`default`) mean `managed` — today's zero-config behaviour.

| transport | meaning | local daemon? |
| --- | --- | --- |
| `managed` | borz launches and owns a Chrome under the profile's runtime dir | yes (auto-spawn) |
| `cdp` | attach to an existing CDP endpoint (`cdpUrl` or `cdpHost`/`cdpPort`); if it is unreachable the command fails loudly — borz never launches a browser for a cdp profile | yes (auto-spawn, pinned to that endpoint) |
| `remote` | send every command to a remote `borz server` (`url`, `token`) | no |

```bash
borz profile list                                # what each name means — run this first
borz profile add mini --remote http://100.64.0.1:13333 --token "$BORZ_TOKEN" \
    --description "Mac Mini's logged-in Chrome"
borz profile add mdt --cdp 127.0.0.1:19845 --idle-tab-timeout 0 --max-tabs 30
borz --profile mini open https://example.com     # HTTP to the Mini server
BORZ_PROFILE=mdt borz snapshot                   # tunnel-attached Chrome
```

Optional `description` is one line of free text on any transport, set with
`--description <text>` (`""` clears it) and shown by `profile list` / `profile
show`. It never affects resolution; it is how a caller learns which browser a
profile name actually drives, so read it before picking a profile rather than
inferring intent from the name.

Optional `idleTabTimeout` (minutes, 0 = never auto-close idle tabs) on
`managed`/`cdp` profiles is honoured by auto-spawned daemons; precedence is
`--idle-tab-timeout` flag > `BORZ_TAB_IDLE_TIMEOUT` env > profile > 0, so
idle-tab auto-close is disabled by default.
It is rejected on `remote` profiles. Verify via `idleTabCloseMinutes` in
`borz daemon status`.

Optional `maxTabs` (0 = unlimited) on `managed`/`cdp` profiles limits retained
page tabs. When the count exceeds the cap, the daemon immediately closes the
oldest non-current tabs. Precedence is `--max-tabs` > `BORZ_MAX_TABS` > profile
> 30. It is rejected on remote profiles; verify via `maxTabs` in daemon status.
For tabs already open before daemon startup, oldest means daemon-observed
registration order because CDP exposes no original creation timestamp.

Deprecated but still working: `--remote` = `--profile remote`; `borz client
setup` writes the `remote` profile; a legacy `~/.borz/client.json` is migrated
into profiles.json automatically (and left on disk). `--remote` combined with
an explicit `--profile` is an error.

`BORZ_CDP_URL` is a legacy override for the default profile only. Named
managed profiles reject it; use a declared `cdp` profile for an external CDP
endpoint. Managed browser identity and lifecycle locks are profile-scoped, so
concurrent CLI processes converge on one daemon and one recorded Chrome.

## MCP (for AI agents)

```bash
borz mcp   # stdio MCP server
```

MCP client config (e.g. Claude Code `.claude/settings.json`):

```json
{ "mcpServers": { "borz": { "command": "borz", "args": ["mcp"] } } }
```

Tools (44 total):

- **Navigation:** `browser_navigate`, `browser_back`, `browser_forward`, `browser_refresh`, `browser_close`
- **Interaction:** `browser_click`, `browser_hover`, `browser_fill`, `browser_type`, `browser_check`, `browser_uncheck`, `browser_select`, `browser_upload`, `browser_filechooser`, `browser_press`, `browser_page_visibility`, `browser_clipboard_write`, `browser_scroll`
- **Browser testing:** `browser_webauthn` (typed tab-scoped WebAuthn virtual-authenticator lifecycle)
- **Observation:** `browser_snapshot`, `browser_screenshot`, `browser_viewport`, `browser_get`, `browser_eval`, `browser_term_text`, `browser_wait`
- **Tabs:** `browser_tab_list`, `browser_tab_new`, `browser_tab_select`, `browser_tab_front`, `browser_tab_close`
- **Diagnostics:** `browser_network`, `browser_console`, `browser_errors`, `browser_doctor`
- **Extension-backed Chrome APIs:** `browser_extension_status`, `browser_extension_call`, `browser_bookmarks`, `browser_history`, `browser_downloads`, `browser_windows`
- **Site adapters:** `browser_site_list`, `browser_site_info`, `browser_site_run`

Recommended agent flow: `browser_tab_list` → `browser_navigate` (reuses tab with same URL unless `new=true`) → `browser_snapshot` → `browser_click`/`browser_fill`/`browser_press` → `browser_network`/`browser_console` to diagnose.

## HTTP / REST (for remote integrations)

```bash

# refuses to bind non-loopback without --token
# --ensure-browser: server launches/relaunches the managed Chrome whenever the
# (loopback-only) CDP endpoint is unreachable — no external keep-alive needed
```

## Environment

- `BORZ_CDP_URL` — override CDP endpoint (managed-transport discovery only)
- `BORZ_PROFILE` — default profile for this process (see Profiles above)
- `BORZ_MAX_TABS` — maximum retained page tabs (`0` = unlimited; default 30)
- `BORZ_HOME` — config dir (default `~/.borz`)
- `BORZ_SESSION_ID` — override the CLI's automatically derived operational-log session id
- `BORZ_TOKEN`, `BORZ_SERVER_HOST`, `BORZ_SERVER_PORT` — server mode
- Legacy `BB_BROWSER_*` env vars are still accepted during the rename transition.

## Key behaviors to remember

- **`open` reuses tabs with the exact same URL** (focus only, no reload). Use `--new` / `new: true` to force a fresh tab.
- **Use viewport emulation for RWD checks.** `borz viewport mobile`, `browser_viewport {preset:"mobile"}`, or `/v1/viewport {preset:"mobile"}` applies a 390x844 mobile/touch viewport to the current tab; reset with `viewport reset`.
- **`--wait-for <selector>` works on every action that changes the page**, not just `open`: `click`, `hover`, `fill`, `type`, `check`, `uncheck`, `select`, `press`, `scroll`, `eval`, `back`, `forward`, `refresh`. The daemon runs the action, then polls `document.querySelector(...)` on a 100 ms tick until non-null or `--timeout <ms>` elapses (default 10000 ms). Prefer it over `wait <ms>` for any DOM change.
- **`--pre-delay <ms>` / `--post-delay <ms>` (CLI global; `preDelayMs` / `postDelayMs` on REST; `preDelay` / `postDelay` on MCP page-changing tools)** absorb the `sleep N && borz ...` / `borz ... && sleep N` shell pattern into a single daemon round-trip. Pre-delay sleeps before the action; post-delay only fires when the action succeeds. Both are capped by the 30 s daemon command timeout — for longer pauses use a separate `borz wait` call. Prefer `--wait-for` over `--post-delay` whenever a DOM selector is available.
- **`eval` auto-wraps top-level `await`** in `(async () => { return (<script>) })()` so `await fetch(...).then(...)` works without manual IIFE boilerplate. Disable with `--no-auto-await`. Already-async-IIFE scripts are not double-wrapped.
- **`eval --unwrap`** prints `resp.data.result` raw — strings without surrounding quotes, everything else JSON-pretty. `--jq` and `--json` still take precedence when set.
- **Non-loopback bind requires a token.** The server refuses to start otherwise.
- **Site adapters have an explicit scope.** CLI and MCP default to `client`: they read the adapter and SHA256 trust beside the CLI/MCP process, build its JavaScript locally, and can send it through a managed, cdp, or remote profile. `--scope server` / MCP `scope:"server"` uses `/v1/sites/*`, so catalog, trust, and usage come from the selected daemon's `~/.borz/sites` or `~/.borz/bb-sites`. Direct `/v1/sites/*` calls are always server-scoped. `site update/new/lint/trust` are client-only; manage server adapters on the daemon host. When no tab is specified, adapters reuse or open their domain first; explicit tabs still enforce the domain guard unless `force` is set.
- **Backgrounded tabs report `visibilityState: "hidden"` and pages throttle on it.** Many apps (Teams, Slack, most upload flows) refuse to start work while hidden — the request is simply never made. `borz tab front` / `/v1/tabs/front` really unhides the window (restores it if minimized, then activates + focuses), and needs no Chrome extension. When the window must stay where it is (unattended automation on a headless-ish host), `borz page visibility visible` / `/v1/page/visibility` makes the page *believe* it is visible: `document.visibilityState` / `document.hidden` are overridden, a synthetic `visibilitychange` fires, focus is emulated, and the web lifecycle state is set to active. That override persists across navigations in the tab until `reset`, but it cannot un-throttle requestAnimationFrame or compositor rendering — for real rendering use `tab front`.
- **`filechooser` is for file inputs that don't exist in the DOM yet.** `upload <ref>` needs a stable `<input type=file>`. When a site builds the input on click or opens the OS dialog directly, arm `borz filechooser accept <file>` *before* the click: the native dialog is intercepted and fulfilled. Arming is one-shot, like `dialog`.
- **WebAuthn virtual authenticators are tab-session scoped.** For real browser Passkey E2E, run `webauthn enable --tab T`, then `webauthn add --tab T --json`; the safe add defaults are CTAP2/internal with resident keys, UV capability, `isUserVerified=true`, and automatic presence. Keep `data.result.authenticatorId` for `credentials`, `set-user-verified`, `set-automatic-presence`, and `remove`; finish with `disable`. This is a typed WebAuthn surface, not arbitrary raw CDP.
- **Network/console/error buffers are per-tab rings.** Use `--since last_action` for incremental queries.
- **Operational logs are persistent and privacy-safe by default.** `borz logs tail` shows recent tool/action outcomes; `borz logs stats --since 7d` aggregates failures and latency. Raw field text, scripts, clipboard data, headers, URL queries, snapshots, and response bodies are never logged.
- **A surviving local daemon recovers its managed browser automatically.** If Chrome exits while the daemon remains alive, the next CLI/MCP command relaunches the managed browser on the daemon's existing CDP port and reconnects. Custom/remote CDP endpoints are never launched locally.
- **The optional Chrome extension unlocks browser-level APIs CDP cannot see.** Use it for all-domain cookies, bookmarks, browsing history, downloads, windows, tab groups, and browser-level event streams. Commands and MCP tools report a clear "no extension connected" error when it is missing.

## Minimal end-to-end example

```bash
borz open https://news.ycombinator.com
borz snapshot -i -c
borz click 5
borz eval "document.querySelector('.title').textContent"
```
